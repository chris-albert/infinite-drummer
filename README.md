# Infinite Drummer

A Max for Live MIDI effect that makes programmed drums sound played. Built for
Infinite Bits' Ableton → Roland TR-8S rig, where the sequences live in Live and
the TR-8S just plays what it's sent. Every instrument gets its own humanize
settings on one panel, so the hats can be loose and the kick can stay tight.

```
Live drum clip ──> [Infinite Drummer] ──> track "MIDI To": TR-8S
                    per-instrument timing, velocity, chance
                    + kit-wide drift, accents, soft-hits-drag
```

## What it does

Each incoming note is matched against the 8 instrument rows (by MIDI note).
Matched hits get:

| Control | Per row | What it does |
|---|---|---|
| **Name** | ✓ | A label for the row, so you can tell the hats from the snare. Click, type, press Enter. Defaults to the TR-8S abbreviations. Saved with the Live set. |
| **Note** | ✓ | Which MIDI note this row catches. Defaults are the TR-8S map (BD 36, SD 38, CH 42, OH 46, RS 37, HC 39, LT 43, MT 47). |
| **Jitter** | ✓ | Random timing, ± this many ms. Hats want more than kicks. |
| **Late** | ✓ | Fixed timing bias in ms. Positive lays back, negative pushes (needs Lookahead). |
| **Vel ±** | ✓ | Random velocity spread. |
| **Accent** | ✓ | Velocity shaping by grid position: hits on the beat get +Accent, the "&" gets a quarter of it, the "e" and "a" lose half. The bar's downbeat gets an extra half. |
| **Chance** | ✓ | Probability the hit plays at all. Great for ghost notes and busy hat patterns. |
| **Amount** | global | Scales every deviation (timing and velocity) from 0 % to 200 %. This is the performance knob: map it to a controller and ride it. Chance is not scaled. |
| **Drift** | global | A slow push/drag of the whole kit, ± this many ms, following a sine that loops every **Drift bars** bars of song position. |
| **Lookahead** | global | Delays everything by this much so rows can be *early* (negative Late). Compensate with the track's Track Delay set to −Lookahead ms. |
| **Soft = late** | global | Soft hits land up to this many ms late, hard hits equally early. Ghost notes drag, rimshots dig in. |

Notes that match no row pass through untouched (still delayed by Lookahead so
they stay in time). CC, pitch bend, pressure and program changes pass straight
through. Note-offs follow their note-on by exactly the same delay, and a hit
dropped by Chance drops its note-off too, so the device is safe in front of a
Drum Rack as well as external hardware.

The readout in the bottom-left shows the last hit: the row's name, timing
offset, final velocity and how far it moved.

## Install

Every push builds the device on GitHub Actions: open the run under the
**Actions** tab and download the `InfiniteDrummer` artifact, which holds the
`.amxd`, the `.js` engine and the `.maxpat`. Or build it locally:

```sh
python3 device/build_amxd.py      # writes device/InfiniteDrummer.amxd
```

1. Drag `InfiniteDrummer.amxd` onto the MIDI track that feeds the TR-8S,
   before the External Instrument (or as the last MIDI effect if you're using
   the track's MIDI To routing).
2. Keep the `.amxd` next to `infinite-drummer.js` (the `device/` folder, or
   the unzipped artifact). An unfrozen device finds the engine by looking
   next to itself. If you want a single file to hand around, open the device
   in Max and freeze it.
3. Check that the TR-8S is actually responding to MIDI velocity (System →
   MIDI settings). If every hit is full volume, the velocity work is invisible.
4. If you use negative Late values, set Lookahead to cover them and put
   −Lookahead ms in the track's Track Delay so the kit stays on the grid.

Live 11 Suite bundles Max 8.5, which is what this targets. Live 12 works too.

## Suggested starting points

- **Tight electronic:** Amount 60 %, Drift 0, Soft 0, Jitter 2–4 on everything.
- **Live band:** the defaults. Drift 3 ms over 8 bars, Soft 2 ms, hats Jitter 8
  with Vel ± 18, snare Late 2.
- **Falling apart on purpose:** map Amount to a fader and push it past 100 %
  for the last chorus.

## Development

```sh
node test/engine.test.js          # engine logic under node with stubbed Max globals
python3 device/gen_maxpat.py      # regenerate the patcher (UI layout + plumbing)
python3 device/build_amxd.py      # wrap the patcher in the .amxd container
```

- `device/infinite-drummer.js` is the whole engine. It runs in a `[js]`
  object, so it is ES5 only. `autowatch = 1` hot-reloads it while the device is
  open in Live; there is no parameter state to resync because the engine reads
  the controls by scripting name each time a note arrives.
- `device/infinite-drummer.maxpat` is generated by `gen_maxpat.py`. CI
  regenerates it on every push and commits the result back on `main`, so you
  only need to run the generator locally to see the change in Live. The
  patcher is deliberately small: midiin → midiparse → engine → pipe → midiformat
  → midiout, plus a `[transport]` query before each note for the accent grid
  and drift. The 61 UI controls live in presentation mode; each row's Name is
  a `textedit` bound to a `pattr` Blob parameter, which is what makes the text
  persist in the Live set. If you start editing
  the UI in Max, treat the `.maxpat` as the source from then on and drop the
  generator, rather than keeping both.
- Right-click the device title bar → Open Max Window to see engine messages.
  Sending `status` to the `[js]` object dumps every control it can see;
  a control it *can't* find is reported once and read as 0.

### Known limits

- `[js]` runs on Max's low-priority thread, so on top of the jitter you ask
  for there is a small amount you don't (typically under a couple of ms,
  more if the Live UI is very busy). For a humanizer that's inside the noise,
  but this is not the device to use for sample-tight triggering with Jitter 0.
- Accent assumes 16th-note feel in the current time signature. Triplet grids
  get no accent pattern (the other controls work as usual).
- The device can only delay, never advance. "Early" is always relative to
  Lookahead.
